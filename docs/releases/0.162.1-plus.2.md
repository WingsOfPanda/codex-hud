# Codex Plus 0.162.1-plus.2

This release supersedes `0.162.1-plus.1` for fleet rollout. It fixes two paths
that could bypass fleet-config's stock-daemon wrapper:

- The launcher preserves the caller's PATH for native launches, `run`, and
  `park`. A `codex` command inside `codex-plus run` therefore reaches the fleet
  wrapper rather than the release's private native binary.
- `/daemon` is read-only, with status and Close. Both update choices are removed.
  Stale update events cannot exit the TUI or schedule an update, and the CLI
  rejects any remaining TUI daemon-update handoff before launching a process.

Upstream remains `rust-v0.162.1`, commit
`092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`. Package source snapshot:
`f0b0ae2fe4ac7f24c62c677a8e6586b1d59197b6`. Frontend patch SHA-256:
`8ae7388f60c52e668c98730e661f597c505e94d9e02e3d35b9f9e8b711c325b5`.
Both targets use Rust 1.99.0, GNU release builds, and glibc 2.39.
Voice remains intentionally excluded. No backend patch, database migration,
shared-daemon replacement, or upstream-version change is introduced.

## Verification

Both final packages were extracted and tested on their native architectures.
All 17 terminal stages, eight managed-shell cases, Code Mode, CLI/stdio execution,
and official-stock-daemon park/wake passed. Each park check produced one callback.
Package inventories and hashes remained unchanged after runtime tests; official
binaries and test fixtures were unchanged. Model fixtures stayed on loopback.

The reported `codex-plus run -- codex app-server daemon update --from-cli --yes`
command was tested with a fake HOME containing `.local/bin/codex` and a stubbed
package executable. The fleet wrapper was selected, arguments and exit status
were preserved, and no real daemon update ran. Native regressions cover both
update sources, local/embedded/remote menus, and direct stale update events.
Source checks cover clean/reverse patch application and absence of backend edits.

Primary ARM acceptance exposed a fixture race: the test waited for shell rows
then immediately asserted worker metadata, which refreshes independently. The
fixture now waits for both observations within the existing timeout. The original
failure is retained in the evidence; this test-only correction changes no package
bytes.

The full runtime gate retains **8/9 passing checks and exit 1** on each host:
direct bundled-bwrap namespace setup returns `setting up uid map: Permission
denied`. The official helper fails identically. This is the existing **host
policy, same as stock, unused by the configured fleet** limitation. Separate
supported CLI sandbox tests pass for both stock and Plus, including read-only
enforcement. No OS security policy was changed; the CLI's chosen helper path was
not traced.

## Rollout

Fleet-config owns archive/tree pins, installed wrappers, stock-daemon maintenance,
and rollout acceptance. Existing processes must be restarted or resumed into the
new release to pick up these fixes. Keep previous packages while they remain in
use. Directly invoking a private package binary bypasses fleet wrappers by design;
daemon maintenance must use the stock command through fleet-config.

Publication does not install anything. Real fleet PATH/AP acceptance remains for
the separately approved rollout. The full upstream suite and older glibc versions
were not tested. Published plus.1 asset bytes remain unchanged.

This companion note stays outside the hashed payload; its hashes describe the
qualified archives rather than creating a self-referential package tree hash.
