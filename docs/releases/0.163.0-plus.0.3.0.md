# Codex Plus 0.163.0-plus.0.3.0

The installed helper is now Rust: `park`, `run`, `advisor`, observation and
supervision use `bin/codex-plus-runtime`. Packages contain no Python source,
bytecode, interpreter or libpython dependency. Build/test tooling may still use
Python; system Python stays installed. SQLite is bundled in the helper.

The normal `← for agents · ? for shortcuts` row and its empty reservation are
removed. Shortcuts, explicit help and contextual controls remain available.
The foreground advisor has a locally timed conversation row; workers, background
commands, advisor status, alerts and overflow retain their three-row total cap.
HUD refresh performs no model calls. Native sessions restart with `codex resume`
to load the updated display.

## Verification and limits

Each extracted optimized package passed 21 terminal stages, eight shell-policy
cases, native cancellation and official stock-daemon park/wake. Tests cover
start/resume, editable composers, split-pane isolation, resize, the three-row
activity budget and AP's prompt-within-last-six-nonempty-lines condition.
App-server stdio, the package's code-mode host and bundled resources, finite
`exec`, argument/exit forwarding, launcher symlinks and PATH dispatch pass.
Daemon-update wrapper checks use stubs, not a real daemon update.

Both actual shipped Rust helpers passed 19 coordinator cases, 16 runner cases,
five upgrade cases, stock background/advisor/foreground checks and seven advisor
groups. ARM also reran all five stock lifecycle interruption/restart scenarios.
Foreground advice was held for 65 seconds with no polling turn or park callback.
All identities, frozen callback text, cancellation evidence and ambiguous stock
delivery remain preserved. Three inherited Python monkeypatch runner tests are
skipped; they do not execute Rust. Full upstream Rust tests, disk-full injection,
the complete six-attempt supervisor backoff and older glibc baselines were not
qualified. Prior source evidence includes 51 Rust unit tests per architecture
and 1,110 native bottom-pane tests with one existing ignored test.

Independent root acceptance used fresh archive extractions on the native hosts,
reran package gates, coordinator/upgrade and foreground checks, and confirmed
unchanged archive/manifest/official-binary hashes. ARM passes all nine package
gates. X86 passes eight of nine: raw bubblewrap cannot set up its UID mapping
under existing host policy, identically to official stock. Dependency resolution
and the supported CLI read-only sandbox pass for both. No host security policy
was relaxed, and this raw namespace restriction remains an explicit limit.

Preserved failures and resolutions:

- X86's first build-evidence driver incorrectly probed the internal runtime with
  `--help`; the binaries compiled successfully. The driver now uses `park --status`.
- ARM's initial driver raced extraction, then lacked pyte. Qualification reran
  after extraction using an existing private pyte 0.8.2 installation.
- A raw credential-pattern scan matched adjacent ELF literals: the four-byte
  public `ghr_` prefix followed by a separate `path` literal. ELF string lengths
  and the unchanged upstream prefix table establish the false positive.
- Independent ARM smoke exposed a bare test command sometimes resolving to the
  installed helper. Final tests pin both commands to the private canonical
  launcher and verify its invocation trace, including a conflicting PATH test.
  The failed attempt's external-request activity is unknown because the old
  fixture removed its temporary child logs. No surviving owned process remained.
  Final corrected qualification uses loopback providers and private homes.

The native package files stayed byte-identical after testing. Source, build,
root acceptance, retained failures and scan evidence are recorded in
[qualification evidence](https://github.com/WingsOfPanda/codex-plus/blob/0.163.0-plus.0.3.0/docs/evidence/plus030-release.json).
These tests do not install the release or
modify production ledgers, wrappers, active trials or shared daemons.

## Rollout and rollback

The fleet baseline is stock 0.163.0 with Plus 0.163.0-plus.0.2.0. **No shared-daemon
restart is needed.** This is the protocol-1 Python to protocol-2 Rust bootstrap:
hold new parks and reach a quiet checkpoint with no Python/native helpers,
armed parks or open callbacks. Preserve the ledger; do not cancel or resend old
callbacks merely to reach the checkpoint. A TUI restart alone does not transfer
an existing Python observer.

Fleet-config updates its native-helper detection and explicitly retains the last
qualified Python package and interpreter beyond ordinary previous retention.
Every rollback is quiet. Compatible strictly newer Rust protocol-2 packages at
the same upstream/target can subsequently transfer cooperatively. The ledger and
status schemas remain version 1; global workflow syntax and wrapper routes stay
unchanged (`agents_md: null`). Stock enqueue/ack ambiguity is still visible and
is not blindly resent; exactly-once model or tool execution is not claimed.

Fleet-config owns staging, its rollout go, installation, global policy and pins.
Merging the topic branch remains a separate user gate. Compiler caches are kept
for the next build; higher parallelism is to be benchmarked, not assumed faster.
