# Codex Plus 0.165.0-plus.0.4.9

This release moves the Plus frontend to official **Codex 0.165.0**, preserving
compact display, Morandi, worker/background status, Goal and Ultracode. The helper
version remains **0.4.9** because its runtime source is unchanged. The official
stock daemon remains unpatched.

Upstream's default-on reasoning-effort updates are preserved. Supporting OpenAI
models send configuration updates when effort changes while retaining request
effort and the prompt-cache key. Actual wire and persisted-history checks passed
on both architectures. This establishes protocol behavior, not a measured
paid-provider cache-hit rate or cost saving. The new default needs stock0.165.

## Paired cutover and rollback

Coordinator protocol5 and execution record format1 are unchanged. `agents_md`
is null; no new configuration key or global instruction block is needed.
Retain **0.163.0-plus.0.4.9**. The handoff requires a quiet checkpoint, drained
executions/relevant Advisor calls, and **daemon and session restarts**.
Fleet-config owns rollout and its user approval.

On each quiet host under its maintenance hold, perform the operator's stock npm
installation, Plus installation and
`codex-stock app-server daemon update --from-cli --yes` back to back.
Start no new work between them. After the pair switch, exit and resume old048/049
TUIs before ordinary work. Preserve packages still used by another workstream.

Before cutover, record and preserve old stock CLI/daemon identities and restoration
inputs alongside retained Plus. Automatic old-stock retention is not assumed.
Qualified previous official binary SHA256 values:

- x86_64: `399ff69c431c066e40de318fba45c2b07f45a76b19939d247ee4828fc70c4215`
- aarch64: `8a96f66d059d653e68bfd5f3c79337e6f1d7d170d80bf705eb7d0249b34c0ece`

Rollback restores stock0.163.0 through npm and the daemon updater together with
Plus0.163.0-plus.0.4.9 at another user-authorized quiet checkpoint. Re-pinning Plus
alone is insufficient. No snapshot restoration was used to pass qualification.

The four observed fleet homes already have `memories/` and retain V1 with
generation/use enabled and version/dual-write unset. Candidate writes and old-stock
default readback passed for that layout. Fresh0.165 homes may select V2: their data
was preserved and explicitly readable by stock0.163, but its unchanged default
remains V1 and does not automatically use the V2 summary. Fresh-V2 rollback is
outside the transparent unchanged-settings fleet claim. No memory policy change
is included.

Publication, main merge, installation and process restart remain separate outcomes.
Fleet-config stages the published handoff before its rollout decision.
