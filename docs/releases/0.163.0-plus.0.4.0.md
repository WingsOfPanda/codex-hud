# Codex Plus 0.163.0-plus.0.4.0

This release keeps OpenAI Codex **0.163.0** and its stock shared daemon. It adds
reviewed long-running jobs and Ultracode, with clearer activity and status displays.

## Changes since 0.3.2

- Workers hand back expected runs over eight minutes, hardware trials and service
  operations for root review before launch. An allowed quick check that overruns
  may finish; eight minutes is not a kill timer.
- `job prepare/launch` freezes reviewed inputs and starts durable executions with
  logs, results, resource coordination and explicit cancellation. Qualified TUI,
  launching-SSH logout and stock-daemon restarts preserve work; completion wakes
  the root without model polling. Unknown outcomes never authorize automatic replay.
- Background rows use short `codex-plus-task` topics instead of long command lines.
- `/ultracode on|off|status` enables an optional root-led phase procedure, worktrees,
  sealed contracts and root acceptance independently of effort. Mode snapshots are
  bound to admitted turns and complete startup instructions survive qualified
  compaction/recovery. It is a guided workflow, not a script scheduler or sandbox.
- Active mode displays beside model/effort: `GPT-6-Astra high ultracode`.
- **Weekly reset** in `/statusline` displays `resets in 2d 5h`, using cached quota
  timestamps and local refresh. Unknown and elapsed deadlines stay explicit.
- Overlapping MCP/web tool rows settle their original indicators; completion and
  interruption no longer leave stale blinking Calling/Browsing rows.

The activity strip remains at most three rows, including alerts and overflow.
Voice remains omitted. Runtime packages require no Python interpreter.

## Qualification

Both complete GNU archives were assembled and tested on their native architecture
from the same clean source commit. Tests used private homes, official 0.163.0
daemons and loopback providers; installed packages, shared daemons and global
configuration were untouched.

- 183 native Rust helper tests passed on each architecture.
- Extracted-package checks cover inventory/mode/tree hashes, ELF/dependencies,
  versions, symlink launcher/PATH routing, `exec`, stdio Code Mode, native terminal
  and shell policy. x86's host-policy exception is described below.
- Park, runner, advisor interruption, seven upgrade checks, six stock lifecycle
  cases, 32 goal scenarios and all 22 detached-job scenarios passed on each target.
- Both architectures passed bootstrap/compaction tests (local/remote, with and
  without pressure), exact Ultracode admission/recovery, countdown and mode-footer
  checks, short shell topics, detached-job HUD, and full native smoke/tool rows.
- Fresh-home `job` and `ultracode` operator probes passed on both extracted launchers.
  Ultracode status initializes a private ledger; it is not filesystem-read-only.
- Dedicated fresh SSH sessions on both hosts proved launching-login closure,
  continued execution, a second launch after logout, graceful/abrupt private-daemon
  replacement and exactly two completion wakes with unchanged execution identity.
- Archive scans found no private state, Python runtime or unaccounted credential
  patterns. Token-shaped matches were resolved using exact pinned-source literals
  and ELF string boundaries; pattern scanning is not an exhaustive secret audit.
- Prior source acceptance also ran the four genuine Codex-worker scenarios:
  honest work, changed assertions rejected, ignored autouse fixture rejected before
  collection, and parallel pieces followed by dependent integration. They are
  distinct from the loopback provider fixtures used for archive qualification.

### Failures, corrections and limits

- **x86 raw bwrap namespace probe:** host policy denied UID-map setup identically
  for official and Plus binaries. Actual CLI read-only sandbox checks passed for
  both. The fleet's configured unrestricted sessions do not use that raw path;
  no host security setting was changed.
- **ARM initial qualification:** four checks failed because the controller's
  temporary path exceeded the Unix-socket limit (the relative-home case reached
  128 bytes). All four passed using a shorter private `/data` path with the same
  archive, executable and timeouts. Original failure reports were preserved.
- Reboot, explicit session/cgroup termination, last-user-service shutdown and
  executor crash are outside detached-execution continuity guarantees.
- Native leaf/worktree instructions do not enforce a separate sandbox or V2
  depth limit. Ordinary worker watches retain their 24-hour bound and per-child
  wake behavior; no automatic whole-workflow replay or final-only fan-in is added.
- The obsolete protocol-3-to-2 rollback harness was not applied to protocol 5.
  No rollback below 0.4.0 is qualified once execution or mode records exist.
- The full upstream Rust suite and a live-provider compaction benchmark were not
  run. Focused frontend Rust tests passed on x86; actual ARM frontend behavior was
  checked through its native terminal/package fixtures.

## Rollout

This is an incompatible **coordinator 3 → 5** cutover; the protocol-4 draft never
shipped. Execution record format stays **1**. Require a quiet checkpoint with no
unresolved executions, and restart TUIs after installation. The stock daemon
needs no restart. Keep native goals and automatic updates disabled.

**Ultracode needs a new session for legacy roots.** Existing threads continue to
work normally through `codex resume`, but resuming alone does not retrofit its
bootstrap. Already qualified roots can resume. Off preserves existing jobs/results.

Fleet wrappers must route `job` and `ultracode` to the helper before applying the
[new global workflow block](https://github.com/WingsOfPanda/codex-plus/blob/0.163.0-plus.0.4.0/docs/releases/0.163.0-plus.0.4.0/agents-block.md). Owner-confirmed quiet still
covers native/AP work outside the maintenance fence. Mode settings/snapshots are
not runnable queues and do not add a blocking quiet count.

Retain `0.163.0-plus.0.4.0` as the first qualified protocol-5 floor. Existing previous/in-use
retention still applies; an older retained folder is not a qualified rollback.
See [fleet details and probes](https://github.com/WingsOfPanda/codex-plus/blob/0.163.0-plus.0.4.0/docs/releases/0.163.0-plus.0.4.0/fleet-contract.md). Fleet installation and
merging the topic branch remain separate user gates.
