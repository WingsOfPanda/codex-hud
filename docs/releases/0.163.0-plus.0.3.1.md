# Codex Plus 0.163.0-plus.0.3.1

This release fixes callback starvation after cancellation/history exhaustion,
advisor process-tree leaks on `/stop`, and relative-home observer startup. It
adds topic-based advisor conversation rows, reduces completed-worker polling,
corrects developer artifact/Code Mode host selection, and includes complete
declaration-backed native dependency notices.

OpenAI stays **0.163.0**. The shared daemon stays stock and needs no restart.
The ledger remains schema 1 and the coordinator remains protocol 2. Voice and
Python runtime files are omitted. Global instructions and wrapper dispatch do
not change. Running TUIs must exit and `codex resume` to load the new display.

## Behavior fixes

- Batch selection/assignment and cancellation serialize in an immediate
  transaction. Never-dispatched legacy callbacks stranded by the older race
  retire locally without changing park provenance.
- Bounded consumed-history exhaustion preserves the affected callback's
  uncertainty while fresh independent completions proceed. Transport failures
  still propagate; unknown stock enqueues are never blindly resent.
- Relative `CODEX_HOME` resolves before package directory changes and re-exec;
  existing symlink protections remain.
- An acknowledged detached Linux subreaper guard cleans advisor/Git children
  after owner/terminal-group death, including descendants in separate sessions.
  Git metadata probes disable fsmonitor locally. Result transport is bounded
  at 512 KiB independently of schema character limits.
- The conversation shows `• Advisor on <short topic> · M:SS`; the model and
  effort remain in the footer. Explicit foreground topic markers identify
  opaque wrappers. Unrelated shells, completion evidence, draft editing and
  the three-row activity/AP readiness budget are preserved.
- Only active/waiting workers require turn-history RPCs; inactive members
  remain available for grouped totals.
- Cargo artifact messages select actual outputs, and developer builds include
  the separate Code Mode host package with pinned V8 resources.
- Native notices cover 1,066 x86 / 1,063 ARM production packages and 146 helper
  packages per target. Six curated resolutions preserve standard declarations,
  labeled canonical terms and independent ICU/Microsoft/Rust notices.

Stock enqueue/acknowledgement ambiguity remains visible; this release makes no
exactly-once model/tool side-effect or reboot-persistence claim.

## Preserved failures and limits

- On x86, directly launching bundled bwrap fails UID mapping under this host's
  existing AppArmor/user-namespace policy, identically to the official package.
  Both Plus and official CLI read-only sandboxes enforce write denial. The
  policy was not changed; the fleet uses danger-full-access. This is an accepted
  stock-equivalent host restriction, not a passed raw namespace test.
- ARM's first offline metadata collection requested uncached `alsa 0.11.0`;
  a bounded locked fetch populated the existing private cache. Voice remains
  omitted. Native compilation was not repeated for this metadata failure.
- ARM's first relative-home upgrade fixture constructed a 120-byte lexical
  Unix-socket pathname, exceeding Linux's 107-byte pathname budget. The full
  seven-case suite passed with a shorter private `/data` temporary root; failed
  evidence was retained. No product/source change was required.
- Full upstream Rust tests, older-glibc compatibility, disk-full injection and
  every possible credential encoding were not exhaustively tested. Historical
  source/development checks are not substituted for these archive results.

## Rollout and rollback

`daemon_restart=false`, `quiet_checkpoint=false`, `session_restart=required`,
`agents_md=null`. Installed protocol-2 0.3.0 helpers at the same upstream/target
can transfer cooperatively after their cycle; the installer switches `current`
without signalling them. Fleet-config should verify each helper's package-root
after rollout. Unsupported protocol/upstream/target combinations still require
its quiet checkpoint. Every rollback requires a quiet checkpoint.

Retain Python **0.163.0-plus.0.2.0** until the user decides to retire that fallback
after corrected Rust rollout checks and a 24-hour operational soak. This release
does not retire it, install anything, restart the daemon or merge the topic branch.

Detailed per-target commands, raw failures, reviewed artifact findings and root
gates are summarized in `docs/evidence/plus031-release.json`. Publisher and fleet
rollout approval remain distinct; fleet-config stages/tests the published tag
before requesting the user's rollout go.
