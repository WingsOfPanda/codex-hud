# Codex Plus 0.163.0-plus.0.3.2

This release adds Plus-owned `/goal`: persistent objectives with exact-turn
checkpoints, event-driven completion wakes, and a genuinely Idle main thread
while registered shell jobs or native workers run. It also aligns standalone
worker tokens with current-turn elapsed time and fixes recent-process lookup in
long threads.

OpenAI stays **0.163.0** and the daemon binary stays stock. This release changes
the coordinator protocol from **2 to 3**. It requires a quiet cutover, supported
native-goal disabling, a stock-daemon restart, wrapper dispatch for `goal`, and
TUI restart. Voice and Python runtime files remain omitted.

## Goal behavior

`/goal` controls one Plus objective per interactive root and retains history.
The existing right input indicator displays active, waiting, needs input,
paused or complete without increasing the three-row worker/job/advisor strip.
Input remains editable while waiting; healthy observation and display refresh
make no model calls. Any newly completed goal job can wake the parent while
other jobs run; already accepted result IDs do not wake it again.

Goal IDs, revisions, exact-turn admissions, input epochs and frozen dispatch
identities reject stale decisions. The coordinator stages Continue, Wait,
NeedsInput or Complete and applies it only after positive successful terminal
evidence. Missing checkpoints, repeated lack of progress and uncertain outcomes
require input. Ordinary input has priority. Pause/edit/clear preserve running
jobs and their results while suppressing future goal continuation.

Scheduled reviews default off; optional one-hour or two-hour reviews coalesce
missed intervals and do not poll healthy waiting. Hard token/time budgets are
not implemented. Recovered work after an unwatched gap is report-only until
renewed direction. Closing the TUI does not stop detached observation; a cold
resume can restart the observer. No reboot service is installed.

Acknowledged queue handoffs receive a bounded metadata-only settlement window.
Recovery barriers also cover the interval before a report is prepared; old
stock work cannot clear them without positively accepted fresh user direction.

## Limits

- Queue acknowledgement loss cannot guarantee exactly-once model or tool side
  effects. Uncertain submissions are preserved rather than blindly resent.
- Stock recovery can independently replay already-admitted interrupted work
  before Plus reconnects. The approved Q18 exception remains; Plus does not
  authorize new continuations through that exception.
- Read-only/Plan or workspace permissions can deny model checkpoint writes.
  The safe outcome is NeedsInput, without expanding sandbox permissions.
- Plus controls its own loading paths. Arbitrary same-user clients deliberately
  re-enabling native runtime overrides are outside its ownership contract.
- Full upstream tests, older-glibc compatibility, every instruction-boundary
  crash and long-duration soak are not established by bounded release checks.

extracted and tested on their native architecture with private Codex homes and
loopback providers. No external model requests were made by acceptance.

- Per target: 120 Rust runtime tests; all 32 goal cases; two actual goal TUI

- Both targets exercise actual quiet rollback with the previous 0.3.1 helper

### Preserved failures and accepted limits

- The first ARM candidate exposed a real queue/history visibility race. A
  deterministic regression failed before the ACK-relative settlement fix.
  An additional prepared-report recovery test failed before the full barrier
  authority guard; both fixes and their red/green evidence are retained.
- The advisor completion assertion assumed an older transcript cell remained
  visible in a 16-row tail viewport. Forced ordering and wide/narrow captures
  proved both cells were retained. The fixture keeps its narrow live checks and
  restores normal height before checking completed history; no frontend change
  or timeout relaxation was needed.
- Initial ARM setup used a symlinked temporary directory, correctly rejected by
  secure log opening. All final qualification uses a real private short path.
- ARM's initial 120-test run under default host-wide parallelism exceeded one
  seven-second timing assertion (119 passed). All 120 passed with 16 test threads;
  production source and the assertion were unchanged. Compiler parallelism stays 32.
- x86 raw bwrap namespace/UID mapping remains restricted by the host's existing
  policy, identically for official and Plus. Separate official/Plus CLI read-only
  sandbox write-denial checks pass. Host policy was not changed; the fleet uses
  danger-full-access. The raw namespace gate is an accepted limit, not a pass.
- Three inherited Python-only runner fault-injection mocks are skipped on each
  target; native I/O units and filesystem behavior have separate coverage.
- Root fixture import/CAS setup corrections, initial old-runtime launcher
  selection and operator-fixture SQL placeholder mistakes are preserved as test
  setup failures. They required no additional product behavior changes.

## Rollout and rollback

`daemon_restart=true`, `quiet_checkpoint=true`, `session_restart=required`.
The handoff contains the exact current shell/advisor block plus the approved
Plus-goal documentation pointer, using the fleet-config installation path.

Fleet-config must update helper dispatch and goal-aware quiet checks before
cutover. Preserve existing settings and updater-disable policy while setting
`app-server-daemon/settings.json` `featureOverrides.goals=false` and the agreed
user-level native-goal policy. Verify actual stock startup arguments include
`-c features.goals=false`, and verify controlled Plus loading after the restart.
A config edit or disabled native RPC alone does not establish isolation.

Coordinate quiet root sessions with their owners as well as checking helpers,
armed parks and unresolved callbacks/goal dispatches. Capture any reviewed
native objective before its native API is disabled; existing native goals stay
stored. Conversion is explicit and creates a paused Plus goal.

Fleet-config reported a count-only, read-only snapshot on 2026-10-18: native
`thread_goals` contains zero rows on all four boxes. No box sets `sqlite_home`
and no daemon has `CODEX_SQLITE_HOME`, so their effective SQLite home is
`CODEX_HOME`. This is fleet-reported evidence, not a permanent invariant;
fleet-config repeats capture immediately before rollout.

Retain qualified 0.3.1 explicitly for quiet rollback. Any separately retained
Python archive is not a supported goal-ledger rollback target. Preserve the
ledger and unresolved identities; stop
goal-aware helpers before downgrade and leave custom goals inert. Keep native
goals disabled on rollback. Re-enabling stored native goals is a separate user
decision. Installation and main-branch merging are separate operations.
