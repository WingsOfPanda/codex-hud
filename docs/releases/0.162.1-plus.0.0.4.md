# Codex Plus 0.162.1-plus.0.0.4

This release fixes premature cancellation of parked work when the stock daemon
briefly reports a normal completion as an interruption. Ambiguous origin and
worker turns stay registered until positive terminal evidence resolves them.
Cancellation now records its time, cause, and evidence. Already-cancelled work
is not rearmed, and uncertain delivery is not blindly resent.

Plus now has its own version, **0.0.4**, independent of upstream. An upstream-only
bump can become `0.162.2-plus.0.0.4`; earlier published plus.1–plus.3 names stay
unchanged. This release supersedes `0.162.1-plus.3`.

## Source and compatibility

- Upstream remains `rust-v0.162.1`, commit `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`.
- Manifest `plus_commit`: `6b74025962c2526afcdec5411670393ebbf9deb3`.
- Frontend patch SHA-256: `1f9b93b34a9328874b59b52e29328ecf7b79a0b5580af825a45c804a36723405`.
- Native executables and resources are reused byte-for-byte from qualified plus.3
  builds: Rust 1.99.0, GNU release profile, glibc 2.39. No Rust recompilation was
  needed because upstream, native patch, settings, and resources are unchanged.
- Voice remains intentionally omitted. Canonical runtime layout and tree-hash
  recipe are unchanged. The compact three-row HUD and stock-daemon boundary
  guards are unchanged.
- The shared daemon stays OpenAI's **0.162.1**. No daemon restart, native database
  migration, or global AGENTS.md park/shell block change is needed.

The coordinator SQLite ledger gains additive pending-state and cancellation
provenance columns. Older helpers do not enforce the new uncertainty gates;
a live downgrade of the extended ledger was not qualified. Switching a wrapper does not replace
detached helpers already running; use the coordinated procedure below.

The tag includes later test/procedure/evidence commits. Its commit therefore
differs from the immutable package's `plus_commit`; none of those later files
changes the hashed package payload.

## Qualification and limits

On each native host, the extracted package passed 118 lifecycle tests, 18 bounded
evidence-reader tests, 11 interruption scenarios, seven stock restart/recovery
scenarios, all 18 terminal stages, eight shell-policy cases, and an official-daemon
park/wake case. CLI exec, stdio Code Mode, stubbed wrapper routing, dependencies,
version/launcher behavior, and before/after package integrity were checked.
Helper imports were verified to come from the extracted package.

Primary acceptance independently verified both archive hashes, stubbed wrapper
routing, all 11 interruption scenarios using packaged modules and the official
daemon, and unchanged package inventories and official binaries.

The handoff sidecar passed **19 tests on each architecture**, including three
real stock-daemon transitions: plus.3 to the new helper, recovery with an absent
observer while a job runs, and recovery after completion. Live cases produced
one LIVE COMPLETION each; completion discovered after restart produced one
REPORT ONLY. Frozen uncertain callbacks and cancelled history survived, and an
unrelated private trial remained running. No model polling or external provider
calls were used; normal completion delivery used the loopback provider.

The x86 raw package gate retains **8/9 checks and exit 1**: bundled bwrap cannot
set up its UID map under host policy, identically to stock. This is the documented
**host policy, same as stock, unused by the configured fleet** limitation. The
separate supported CLI read-only sandbox check passes for stock and Plus. ARM
passes all nine gates, including raw bwrap, under the user's existing
`kernel.apparmor_restrict_unprivileged_userns=0`. No security setting was changed
for this release, and persistence of that setting was not verified.

Initial fixture/runtime failures are preserved in local evidence. On ARM, a
detached test environment mixed a custom Python 3.12.11 executable/stdlib with a
3.12.3 shared library; even standalone malformed JSON crashed. Tests passed with
coherent system Python and with the custom runtime's per-job library path fixed.
Test-only corrections address fresh initial HUD metadata, disappearing processes,
and short private Unix socket paths. The sidecar also has regressions for SQLite
hot-journal recovery after stopping a writer and an observer appearing between
process and lock-owner reads. These corrections did not change either archive.

Unavailable, contradictory, or out-of-bounds terminal evidence remains visibly
unresolved. Stock queue/ack ambiguity is not an exactly-once guarantee. The exact
trigger of the historical overnight incident remains unproven; its cancellation
race was reproduced and the regression fixed. Previously cancelled registrations
are deliberately not repaired by this release.

The full upstream suite, older glibc baselines, live fleet handoff, and four-box
installation were not performed by this release task. All tests used private
homes; installed packages, wrappers, shared daemons, and the active GLM trial
were left untouched. Glibc 2.39 is the tested baseline, not a measured minimum.

## Observer handoff and rollback

Fleet-config owns rollout and requires the user's go in its session. Coordinate
with the selected parent's owner before replacing its detached helpers. Leaving
old helpers alone preserves running jobs, but keeps the old missed-wake behavior
for that parent; simply restarting the TUI does not upgrade detached helpers.

Use [the exact observer-handoff procedure](https://github.com/WingsOfPanda/codex-plus/blob/0ddc0ef26c556a57209498514229dca2abfdf818/docs/observer-handoff.md).
The source-only sidecar is intentionally outside the frozen package:

- Sidecar source commit: `0ddc0ef26c556a57209498514229dca2abfdf818`.
- Script SHA-256: `bd6f890cbfd8bb0bc9b000c3ae1188f10b36dcf576f2e7c26588d315e962fca3`.
- [Pinned script download](https://raw.githubusercontent.com/WingsOfPanda/codex-plus/0ddc0ef26c556a57209498514229dca2abfdf818/scripts/handoff-observer.py).

Inspect first. Explicit handoff requires a loaded idle root and no new selected
registrations. It signals only verified helpers, lets SQLite recover a stopped
writer's journal, backs up the ledger before migration, launches the new helper,
and verifies preserved identities/frozen callbacks and new observer ownership.
Failures retain private audit evidence without restoring the ledger or resending
callbacks. Use coherent `/usr/bin/python3` and the exact commands in the linked
procedure; no production handoff has been performed here.

Rollback to plus.3 keeps the same stock daemon. Preserve packages still used by
processes, coordinate any helper replacement, and do not restore an older ledger
snapshot after possible delivery. Older helpers lack this fix; a wrapper rollback
alone does not downgrade helpers already running.

After fleet rollout, ordinary panes pick up the native package with exit and
`codex resume`. `hash -r` is needed only for a shell still caching the npm path
from before Plus was first installed.
