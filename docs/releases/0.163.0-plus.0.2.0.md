# Codex Plus 0.163.0-plus.0.2.0

Adds an independent Astra advisor and a bounded shell-wait workflow for native
workers. Retains the full model labels from 0.1.1:

```text
GPT-6.1-Sol (high) · glm upstream contribution · 2:53 · 175M tok
Advisor · GPT-6-Astra (xhigh) · ready · 0 calls
```

`codex-plus advisor --brief TEXT` selects the newest visible numeric-version
Astra that supports `xhigh`, then runs a separate ephemeral, read-only review.
It receives the brief and repository change pointers, not the parent transcript.
Delegation is disabled. Results are structured advice; the main session owns
the decision. The footer shows readiness, consult count, elapsed time, last
duration or error without model polling. Advisor, workers, background shells,
alerts and overflow share the existing three-row total limit required by AP.

Native workers can wait for a finite shell job in one bounded Code Mode cell,
keeping their turn open until they review the result. A 65-second fixture proves
there are no interim model requests. This uses existing execution tools, not
durable child parking; interruption, restart or an expired wait budget still
requires the caller to handle the unfinished job. See
[advisor](../advisor.md) and [worker waits](../shell-workflow.md#native-subagent-waits).

## Verification and limits

Focused native source acceptance passed advisor 8, HUD 38 and shell-policy 16
tests; these overlapping filters are not a unique-test total. Each extracted
optimized package passed 19 terminal stages, eight shell-policy cases and
official-stock-daemon park/wake. Both targets passed 163 helper lifecycle,
upgrade and evidence tests; 11 interruption, seven recovery, normal completion,
nine cooperative, four upstream-boundary, rollback-read and two upstream UI
scenarios. The four worker-wait scenarios cover success, failure, interruption
and budget exhaustion. Advisor acceptance passed seven groups against the
official stock CLI and seven separately labelled groups against the packaged CLI
on each architecture: real OS write denial, exact Astra/xhigh requests, failure
and interruption reporting, and absence of delegation tools in provider requests.

X86 passed 248 unittest methods with no skips or failures, plus the new delayed-log
regression method with two subtests. ARM passed advisor 16,
terminal fixtures 15 and the unchanged 37-test source/packaging/runner rerun;
launcher and Rust unit filters were not repeated on ARM. Root acceptance passed
against the exact final archives on their native hosts, including packaged
advisor, 65-second worker wait, shell policy, TUI, wrapper routing and unchanged
package/official binary hashes. All providers are loopback fixtures; no remote
model requests are used by these release checks.

X86 passes eight of nine package gates. Raw bwrap exits 1 because the host denies
UID-map setup; official stock fails identically. Supported CLI read-only sandbox
enforcement passes for both. ARM passes all nine package gates, including raw
bwrap, with its existing host policy unchanged.

Original failures remain in the evidence: the obsolete one-row shell assertion
on both targets; ARM's existing `/proc` exists/read race after successful process
termination; and the ARM harness expecting eight cooperative methods instead of
seven methods producing nine scenarios. The corrected tracked shell test and
unchanged ARM source suite pass. The corrected cooperative harness passes; no
cooperative tests ran in its first failing attempt. The original x86 assertion
adapter and failed reports are retained; final checks use unmodified final tests.
Independent root ARM acceptance also caught the delayed-log-path example failure
after a successful 65-second command. That failed run is preserved; the corrected
example captures later output before truncation and is checked on both targets.
The long root session also exceeded the park process-selection scan limit of
32 pages. Acceptance used bounded direct waits after reporting the failed
registration; it did not rely on an unarmed callback. That existing limit is not
changed by this release.

Full upstream workspace tests, older glibc baselines and live production advisor
trials are not release qualification. The tested glibc baseline is 2.39, not a
measured minimum. Stock callback enqueue/ack ambiguity remains visible; no
exactly-once external effects are claimed. Advisor reads a live repository, not
an immutable working-tree snapshot, and its private logs require manual retention.
Evidence: `docs/evidence/plus020-release.json`.

## Rollout and rollback

The reported fleet baseline is stock 0.162.1 with Plus
`0.162.1-plus.0.1.0`. This release supersedes the staged 0.163.0-plus.0.1.1
candidate. Fleet-config must move the stock CLI, stock daemon and matching Plus
together: hold new parks, reach a quiet checkpoint, schedule the official-daemon
restart, then restart native sessions with `codex resume`. Use `codex-stock` for
daemon maintenance; the Plus `/daemon` menu remains read-only. Protocol-1 helper
transfer intentionally refuses a different upstream identity.

The same rollout adds `advisor` to the fleet wrapper's helper dispatch and applies
the exact worker-wait/advisor instruction block in `rollout.agents_md`. Leave the
isolated local advisor preview untouched. Preserve previous and in-use release
folders. Building these candidates does not install wrappers, switch packages,
change the shared daemon or modify active GLM registrations.

Every rollback requires a quiet checkpoint and a matching stock CLI/daemon pair.
Upstream migrations 0060/0061 add guardian feedback and unread-thread UI state,
not Plus receipts. Representative private history and pending-queue readability
passed; this is not a universal production downgrade guarantee.
