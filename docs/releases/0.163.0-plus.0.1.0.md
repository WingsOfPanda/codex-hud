# Codex Plus 0.163.0-plus.0.1.0

This release moves the existing Plus 0.1.0 behavior onto OpenAI Codex 0.163.0.
It preserves the three-row worker/shell footer, managed shell display, park/wake
coordinator, conservative callback recovery, and compatible higher-version helper
transfers. The daemon remains OpenAI's stock implementation.

## Upstream changes and Plus adaptation

Upstream adds searchable `/config` preferences, selectable footer text, revised
status styling and terminal program status. It also enables interruption of Code
Mode cells and their nested calls, improves saved-thread permission restoration,
and removes bundled patched zsh in favor of the standard shell executor.
`instant_interrupt` was already enabled in our 0.162.1 baseline; the material
default change here is `code_mode_interrupt`. See the
[upstream release notes](https://github.com/openai/codex/releases/tag/rust-v0.163.0).

The frontend patch was rebased over the new selection, configuration and retained
side-thread behavior. Its footer still occupies at most three rows including
warnings and overflow, keeping AP's idle prompt within the last six nonempty
lines. The new in-process `/daemon` restart events are blocked alongside both
update paths; the Plus menu remains read-only. Zsh executable/resource/license
requirements were removed from packaging. Voice remains intentionally excluded.

The coordinator's used queue, terminal and thread interfaces remain compatible;
production Python helper code is unchanged from the previous Plus release.
Official 0.163.0 still has no experimental queue-idempotency or delivery-receipt
extension. Unknown enqueue/ack outcomes are not blindly retried. Completion found
after observer recovery remains REPORT ONLY; positively reconfirmed running work
can later produce LIVE COMPLETION.

## Migrations, rollout and rollback

The Plus ledger schema and callback states are unchanged. Official upstream
state migrations add `guardian_review_feedback` (0060) and `thread_read_receipts`
(0061). The latter records unread-thread UI state, not completion-notification
delivery. The experimental Plus receipt migration remains excluded.
[0060](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/state/migrations/0060_guardian_review_feedback.sql),
[0061](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/state/migrations/0061_thread_read_state.sql).

This upstream bump requires **`daemon_restart: true`, `quiet_checkpoint: true`,
`session_restart: required`**. No global park/shell instruction change is needed
(`agents_md: null`). Fleet-config moves the stock CLI, stock daemon and matching
Plus package together. Hold new parks and drain helpers, armed registrations,
open callbacks and other active Codex work before the scheduled daemon restart.
Use `codex-stock` for daemon maintenance. Users exit and run `codex resume` after
rollout; no force-stop observer handoff is used.

The full upstream identity differs, so cooperative transfer from 0.162.1 is
intentionally refused even though both helpers advertise protocol 1. Later
qualified, higher Plus versions on the same upstream can transfer cooperatively.
Every rollback remains quiet and restores a matching stock CLI/daemon pair.

On both architectures, official 0.162.1 successfully opened a private home last
written by official 0.163.0 and read representative completed history and the
unchanged pending queue/client IDs. This establishes the tested readability
case, not universal production rollback safety or support for new-only features.
Preserve state and previous/in-use packages; do not restore a stale coordinator
ledger or replay callbacks to perform a rollback.

## Limits and retained failures

X86's raw package gate remains **8/9 with exit 1** because the host denies bundled
bwrap's UID-map setup identically for stock and Plus. This is the existing host
policy, same as stock, unused by the configured fleet. Supported CLI read-only
sandbox enforcement passes for both. ARM passes all nine package gates, raw
bwrap and both supported read-only sandbox checks under its unchanged user-set
policy. No host security setting was changed.

Initial source failures were retained: incomplete workspace-version reconciliation,
the newly required `excluded_thread_ids` initializer, module visibility, and the
disconnect snapshot's intended stale-HUD row. All were resolved before the frozen
build. The new PTY fixture initially sent Escape immediately followed by text,
which the terminal parser correctly combined as an Alt chord; it now sends the
negotiated explicit Escape sequence while keeping full draft assertions. ARM
qualification used a short private `/data` temporary directory to fit Unix socket
limits, without altering the frozen payload or tests.

The full upstream Rust workspace suite, older glibc baselines and production
rollout were not run. Glibc 2.39 is the tested build baseline, not a measured
minimum. ARM CPU temperature sensors were unavailable. Stock enqueue/ack
ambiguity remains an explicit limit; no exactly-once guarantee is claimed.

Build authorization did not authorize publishing, merging or installation.
Installed packages, wrappers, shared daemon settings, active GLM work and live
registrations were left untouched. Consolidated evidence is in
`docs/evidence/upstream0163-release.json`.
