- **tree_sha256:** `abdb4ff0162548e55d40f70fbb7846b87a5855ac812e60e398629434888b7f94`

The packaging and extraction integrity checks passed. Both the worker's gate and
the primary agent's independent gate passed eight of nine stages, including
terminal behavior, exec, stdio Code Mode,
and official-daemon park/wake. Direct bwrap namespace execution was denied by the
host; the installed official helper failed the identical UID-map operation.
Classification: **host policy, same as stock, unused by the fleet**. On xjp_l20_2,
`kernel.apparmor_restrict_unprivileged_userns=1` restricts unprivileged user
namespaces. Fleet-config specifies `sandbox_mode="danger-full-access"` and
`approval_policy="never"`; AP also launches with
`--dangerously-bypass-approvals-and-sandbox`. This blocked namespace operation is
not part of that configured execution mode and is not a Plus-specific defect.

No host security policy was changed. Package contents and the official binary
remained unchanged after runtime checks. The raw gate retains its failed
namespace check; this qualification does not claim sandbox execution passed.
Sessions explicitly selecting a sandbox remain subject to host policy.

The supported `codex sandbox -- COMMAND` path was checked separately by both the
worker and primary agent. Official and Plus CLIs both executed successfully and
denied file creation under the default read-only policy. Thus the raw bundled
helper restriction must not be described as a failure of the supported CLI
sandbox path. The selected helper path was not traced.

Native ARM qualification is complete for the configured fleet mode: core CLI,

The corrected terminal suites passed on ARM; release-package bytes are unchanged.

Artifacts are under `.build/dual-release/packages/` on xjp_l20_2; the ARM package
is also staged under `/data/liupan/codex-plus-build/packages/` on 910b.
The consolidated [qualification evidence](../evidence/dual-release.json) records
the primary checks, preserved original failures, fixture corrections, and hashes.

Installation remains pending. Fleet-config must pin each target's archive hash
