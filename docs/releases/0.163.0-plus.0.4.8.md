## Runtime changes

- Worker groups show the number of active/waiting members, their longest current
  assignment and summed current-assignment tokens. A latest stock-daemon turn is
  the assignment boundary. Finished members and prior turns no longer inflate the
  footer; unavailable usage remains unknown.
- An execution with an unknown outcome shows `needs review` rather than being
  overwritten by a stale heartbeat label. A recorded finish time freezes duration;
  absent finish evidence shows `?`. Live stale jobs still require investigation.
- Existing verified cleanup resolution removes an Unknown execution's activity
  projection. Its durable unknown outcome and original evidence remain intact.
  No automatic kill, replay or cleanup resolution is introduced.
- Live authorized execution watches can request bounded recovery for unresolved
  cleanup or outcome. Known command exits remain known; routine diagnosis no longer
  forces a user-renewal barrier. Independent work may continue. Restart, cancelled,
  superseded and legacy report-only authority protections remain.

## Compatibility and rollout contract

The release retains coordinator protocol 5 and execution-record format 1, with
an additive default-zero SQLite `jobs.recovery_allowed` marker. Recovery rows keep
legacy `report=1` so old helpers remain conservative. Actual old/new helper reads
and rollback passed on both architectures. Projection JSON adds optional `finished_at`; old clients ignore
it and new clients accept missing/null values. An old helper reprojecting a
resolved Unknown after rollback can restore the old footer behavior without
changing execution truth. The actual 0.4.7 TUI/new helper mix, quiet rollback to
0.4.7 and holds in both directions passed on both architectures.

No new config key or palette setting is required. The
[complete recovery instruction block](../proposals/recovery-agents-block.md) must
be installed with its qualified code and workflow, never beforehand. Advisor and
Plus-owned goals sections remain byte-identical to the previous block. Footer
geometry remains two status rows and up to six activity rows, with explicit help
or search adding its existing row: eight rows normally, nine with explicit help.
AP 0.7.35 classifier and stall-hash replay passed against both native capture
bundles. Replay ran on x86; it does not claim ARM-host AP execution or live nudging.

Rollout: retain `0.163.0-plus.0.4.7`, no daemon restart, quiet checkpoint,
executions drained, session restart required for the new display and instructions,
and the exact full recovery block in `agents_md`. Quiet rollback must restore the
previous 0.4.7 block (`2e5f0b01f3ac15834b8da7c90e436b91e0cc81e3c5ac79d584c2d30603dd8a59`)
alongside the retained package. Both-direction package/record rollback was qualified.
Fleet-config owns authorization and installation; its operator captures full held
status if quiet admission or execution checks refuse the switch.

## Release-process changes

The [release book](../release-book.md) and checklist track ownership, accepted
evidence, timing and each incident's cause/preventive check. The new packaging
preflight checks actual compiler discovery and offline helper/upstream license
inputs before native compilation. A pinned rustc adapter accepts the notice
generator's exact version selector without changing global PATH or toolchains.
Rehearsal and source-test results are distinct from final native package gates.

The final gates use fresh v5 executions; earlier failed attempts remain failed.
Coordinator verifier `65585b488d927d0a86ed26149bb686401f13607b` distinguishes
an audit-only socket check from the original hash-bound removal receipt. Its
supervised AP adapter executes the original tooling and derives a separate receipt
from actual managed results and independent cleanup. This coordinator correction
does not alter the qualified product, execution plan or native receipts.

After x86 qualification, a preparation worker's direct Git status refreshed index
metadata. The full source inventories and index bytes were independently unchanged;
the unlaunched AP preparation was preserved and replaced with fresh AP-only
preparation. The release book records the preventive scratch-index check.

Advisor compatibility uses private providers; no paid call or fresh real-SSH
consultation is claimed. Advisor source is unchanged from 0.4.7. Native test totals
are 205 helper tests plus 213 focused frontend tests per architecture, with none
failed or ignored. Warm-cache stage timings are not an end-to-end release estimate.
Publication does not install packages or merge main; fleet-config owns rollout.

On the x86 qualification host, the raw bwrap UID-map probe failed identically for
official and Plus binaries. Both CLI read-only sandbox checks passed. The original
failed resource check and the explicit host-limitation qualification are retained;
this is not a passing raw bwrap result or a general sandbox waiver.
