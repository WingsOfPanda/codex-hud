# Codex Plus 0.163.0-plus.0.4.3

This source note describes the changes and release requirements. The matching
handoff records qualified archive identities and executed results; this note
alone does not establish package qualification.

## Changes

- Refresh Ultracode on local warm resume and briefly retry empty initial item
  history within the existing bounded retry budget.
- Retry the exact owned empty-rollout metadata error during accepted-input
  settlement without resending input. Longer delays can still exceed the
  existing two-second settlement budget.
- Align the blue Plus goal above input at the right margin. Give Git branches
  a warm color distinct from the blue directory.
- Permit six activity rows, reserving visible worker, native-shell and detached
  job categories. Keep Advisor and overflow separate while typing.
- Hide automatic footer hints and the generic background-availability banner.
  Keep key behavior, explicit help/search, operational context, the working
  `esc to interrupt` indicator and authoritative job records.

Upstream remains official Codex 0.163.0 at
`83086188ae0614bd882818ff1aa23f3194962012`, with Rust 1.99.1,
coordinator protocol 5 and execution-record format 1. No shared-daemon change
or new configuration key is required. Existing `tui.status_line` and
`tui.status_line_use_colors` settings remain valid. Native goals stay disabled.

## Qualification requirements

Build and qualify complete x86_64 and aarch64 archives natively from one frozen
Plus source commit. Check archive/manifest/tree/mode hashes, runtime resources,
launchers, private stock-daemon lifecycle, managed execution and relevant
admission, goal, Ultracode and terminal regressions. Preserve failures and skips
as evidence; successful child gates do not rewrite failed execution receipts.

Use actual 0.4.2 and 0.4.3 helpers to qualify quiet forward/rollback operation
over candidate-written ledger and execution records, holds in both directions,
exact admission snapshots, single workload side effects and no replay. Qualify
other still-running helper versions separately; do not infer simultaneous old
and new TUI compatibility or live running-executor rollback from these checks.

Normal footer captures have at most eight nonempty rows below the composer;
explicit help/search or operational state may add a row. Very short terminals
clip the activity strip while preserving editable input. Capture actual packaged
panes at 100x40 and 80-column splits, including five-field tmux look data:
`cursor_y cursor_x pane_height pane_width cursor_flag`. Cover bare idle, help,
Ultra, two-row draft, busy pairs five seconds apart, busy draft, approval dialog,
native question notes and MCP text forms. AP must replay its actual classifier
and cursor-bounded stall hash; drafts and input forms must not be nudged.

The full upstream suite is not claimed green: six app-session assertions also
fail identically on 0.4.2. Scoped Linux tests explicitly identify the Windows-only
AltGr exclusion. Record native target limitations in the final companion note.

## Fleet contract

Use `quiet_checkpoint: true`, `executions: wait`, `daemon_restart: false`,
`session_restart: required` and `agents_md: null`. Restart obtains the changed
frontend; describe any mixed-version correctness limitations from actual tests.
Retain `["0.163.0-plus.0.4.2"]` after native quiet rollback qualification.
Thus 0.4.1 stops being retained as the rollback floor and becomes removable once
unused; every in-use or unresolved-execution package remains protected.

Fleet staging also requires the AP release implementing cursor-bound bare-main-
composer detection and its installation on every AP-driving box. AP owns that
release and installation; Plus publication does not authorize them.

Build/publication, main-branch merging and fleet deployment are separate actions.
Populate the final handoff only from qualified packages and verify its archive
checksums against GitHub asset digests before sending the published tag.
