# Codex Plus 0.163.0-plus.0.4.5

Qualified on native x86_64 and aarch64. This companion records the final
artifacts and evidence after the package source freeze. Fleet installation is
separate from publication.

This revision carries the build-time preflight, dedicated libtest validator and
release-performance documentation. Runtime source and the frontend patch are
unchanged from 0.4.4; the helper package version is updated. The installed CLI
remains native. Build-time Python tools are kept in the source repository.

The release uses official Codex 0.163.0, upstream commit
`83086188ae0614bd882818ff1aa23f3194962012`, Rust 1.99.1, coordinator protocol 5
and execution-record format 1. The frontend compile origin is
`4a96db52c2e0aeab108ed3e0645bc3ed804a0227`, and its patch SHA-256 is
`caefa0227c491273d7540b2c5f4af336cac67b89f5e9c0b9367d9e55f7c3a4a4`.
Reuse requires exact native file hashes from the qualified 0.4.4 packages.

The shipping Plus source is
`64742e5c5a00d6e7cd754845da421fae329a6e87`. Both new helpers passed 193 runtime
unit tests, two closed-stdio tests, six local advisor contracts and three real
stock-daemon startup cases. The 66 source tooling tests passed on x86; the 20
preflight and four result-validator tests also passed under native ARM Python.
Package identity, inventory, modes, dependency notices, wrapper routing, finite
exec and Code Mode checks ran against the actual new packages on both hosts.

Seven scoped package checks were evaluated per architecture. ARM passed all
seven. On x86 the raw bwrap uid-map check failed identically for the official
and Plus binaries; both CLI read-only sandbox checks passed. The original
failed resource result is preserved as a qualified host limitation, not changed
to a passing raw test.

Fresh native compatibility passed on both architectures: quiet rollback to
0.4.4 over new records, maintenance holds in both directions, seven advisor-mix
checks, and actual old-0.4.4-TUI/new-helper result delivery with correct Claude
display. Both caller/worker directions are compatible because worker identity
is unchanged. Wrong identity is still rejected. Final packaged ARM-to-x86
success and caller-death cleanup passed through real SSH with a deterministic
fake Claude provider. No paid-provider call was made by these release gates.
Every managed execution finished with complete logs and successful independent
cleanup; no owned survivors remain.

The frontend Rust/UI matrices were not rebuilt or rerun. Their original
qualification, 40 native capture states and actual AP0.7.34 classifier replays
are retained with unchanged binary hashes and original source identities,
separately associated with the new manifests. The retained x86 full native
suite reports 5,809 passed, 82 reviewed baseline failures and four ignored;
it is not a green suite or an automatic future failure allowance.

x86 helper compilation took 9.67 s, unit compilation/listing 14.03 s, unit
execution 5.26 s and packaging 45.93 s. ARM equivalents were 23.45 s, 35.13 s,
6.86 s and 53.54 s. Compile concurrency was 16 on each host; test threads stayed
at eight on x86 and four on ARM. Existing Cargo caches and exact qualified
frontend binaries were reused.

ARM evidence collection took 4.32 s; its separate accepted archive transfer
took 273.09 s. These are observed stage durations, not a normalized network or
CPU-scaling benchmark. Stages overlap and must not be added into release wall
time. Source preparation, review, staging, publication and approval time are
outside the native build figures. The final publication receipt records the
request-to-publication interval separately.

This is a helper-only warm-cache release measurement, not a cold frontend
build, a controlled job-count comparison or a promise for future release times.

## Rollout contract

No daemon restart, background.sqlite migration, execution format change or new
config key. `quiet_checkpoint: true`, `executions: wait`,
`session_restart: required`, `agents_md: null`. The global instructions and
advisor defaults are unchanged. Restart loads the new version; it is not a
correctness remedy for the qualified 0.4.4/0.4.5 mix. No installation across an
in-flight advisor consultation is qualified: drain callers and central host,
turns, callbacks and executions, preserve central-host-first ordering, and use
the existing maintenance hold.

Retain becomes `["0.163.0-plus.0.4.4"]`, the qualified quiet rollback floor.
0.4.3 becomes removable only when unused. Preserve packages referenced by
processes or unresolved jobs, the official daemon and native-goal/updater
policy. Fleet-config owns staging, pins and rollout; publication is not rollout
authorization. The existing cursor-aware AP requirement and eight/nine-row
footer contract remain unchanged.
