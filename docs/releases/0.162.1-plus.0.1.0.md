# Codex Plus 0.162.1-plus.0.1.0

This release adds cooperative upgrades to the Python park/wake coordinator.
After an approved package switch, an observer finishes its current delivery
cycle before transferring to the new helper. Watched jobs continue, callback
identities and frozen messages survive, and the stock daemon is unchanged.

Automatic transfer requires coordinator protocol **1**, the same upstream
identity and CPU target, and a strictly higher numeric Plus `M.m.p` version.
Invalid, equal or lower targets keep the current observer running with a stable
warning. A failed exec restores the old working directory and keeps monitoring.
The helper's internal `--package-root` argument protects its source directory
from installer cleanup during exec. No release downloads or model polling occur.

Recovery policy remains conservative: work reconfirmed running can later produce
LIVE COMPLETION; work found completed during the transfer gap produces REPORT
ONLY. Uncertain stock-daemon delivery is not blindly resent. Cancelled work is
not rearmed.

## Qualification and limits

Both extracted packages passed 163 coordinator checks: 27 upgrade, 118 lifecycle,
and 18 bounded terminal-evidence tests. Each passed 11 interruption scenarios,
seven stock restart/recovery scenarios, all 18 terminal stages, eight shell-policy
cases and an official-daemon park/wake case. CLI exec, stdio Code Mode, stubbed
wrapper routing, versions, dependencies and before/after integrity were checked.
X86 additionally passed six launcher tests and 13 packaging tests; ARM passed
11 terminal-fixture checks and the standalone normal-completion integration.

All nine real stock-daemon cooperative scenarios passed on both native hosts:
running jobs, completion in the transfer gap, callback boundaries, rapid A/B/C
selection with a waiting contender, crashes before/after enqueue, and clean
completion. Primary acceptance independently repeated all nine with modules
loaded from each exact extracted archive, verified wrapper behavior, and checked
unchanged package inventories and official binaries. These scenarios seal
distinct private copies of the extracted helper source; they do not claim live
transfer from legacy 0.0.4. The stock daemon may consume a queued callback without
an explicit queue/start request; the fixture records that consumption checkpoint.
Explicit after_start handling and native-worker continuity have focused tests.
All providers were loopback fixtures, with zero remote model requests.

The x86 raw package gate retains **8/9 checks and exit 1**: bundled bwrap cannot
set up its UID map under host policy, identically to stock. This is the existing
**host policy, same as stock, unused by the configured fleet** limitation.
Separate supported CLI read-only sandbox checks pass for stock and Plus. ARM
passes all nine package gates, including raw bwrap, under the user's existing
AppArmor userns policy. No security setting was changed for qualification.

Initial harness failures remain recorded. Packaged upgrade unit tests exposed
source-checkout assumptions in their private fixture context; a test-only overlay
fixed them while preserving packaged imports. ARM's normal fixture needed a
shorter temporary prefix for Unix socket paths under `/data`; its scenario-count
assertion also needed to count callback subcases correctly. A primary-acceptance
script initially confused the manifest-check summary with the full manifest and
was corrected before runtime checks. None of these corrections changed either
archive. ARM used coherent system Python for helpers and the existing UI fixture
environment with its per-job library path; global runtime settings were unchanged.

The full upstream Rust suite, older glibc versions, and production rollout were
not tested. Native code is unchanged, so source Rust/HUD tests were not repeated;
the packaged terminal stages were rerun. Glibc 2.39 is a tested baseline, not a
measured minimum. Stock enqueue/ack ambiguity remains an explicit limitation.

## Installation and rollback

**This first protocol-aware installation still requires a quiet checkpoint.**
The installed 0.0.4 observers cannot learn cooperative transfer while running.
Fleet-config coordinates holding new parks until no helpers, armed registrations,
or open callbacks remain, then installs this release. The historical force-stop
handoff sidecar is excluded from rollout.

For this helper-only release, `daemon_restart` is false, `quiet_checkpoint` is
true, `session_restart` is optional, and `agents_md` is null. New parks use the
fleet wrapper's current package. The native client is unchanged; users may exit
and run `codex resume` normally. Later qualified, strictly higher compatible Plus
releases can transfer observers while jobs run. Every rollback requires a quiet
checkpoint, including a rollback between two protocol-1 releases.

Fleet-config owns pins, installation, compatibility checks and rollback. Preserve
previous and in-use package directories. Do not restore old ledger snapshots or
replay callbacks to facilitate an update. Build authorization does not authorize
publication, merge or rollout; no installed package, wrapper, shared daemon or
active GLM registration was changed by this build.

Consolidated evidence is recorded in `docs/evidence/plus010-release.json`.
