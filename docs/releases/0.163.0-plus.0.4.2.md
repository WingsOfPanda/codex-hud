# Codex Plus 0.163.0-plus.0.4.2

Both native x86_64 and aarch64 packages are qualified from frozen Plus source
`483912b9ed2783cf239e62f3aec3922730979905`. Publication is a separate action.
The release tag may include this later evidence-only companion commit; package
`plus_commit` remains the frozen source above.

## Changes

- Retry temporarily missing exact-turn history without resending accepted input.
- Show worker roles beside model and effort, with `general` for unknown roles.
- Split the status line into identity and statistics rows with distinct item colors.
- Place the blue Plus goal above editable input.
- Keep the prompt within AP's last six nonempty lines. Normal activity uses up
  to three rows; an extra shortcut/history hint reduces it to two with correct
  overflow counts, preserving both status rows and the hint.

Official Codex stays at 0.163.0, upstream commit
`83086188ae0614bd882818ff1aa23f3194962012`. Rust is 1.99.1; coordinator protocol
is 5 and execution-record format is 1. The official daemon is unchanged.
Voice and the Python runtime remain omitted.

## Native acceptance

X86 passed 31 final-archive check groups across the original run and its
continuation. It also retains 35 helper check groups bound to identical helper
bytes and unchanged runtime/test inputs. ARM passed 54 qualification groups,
including all nine package gates, 183 runtime unit tests, 29 runtime acceptance
tests, seven upgrade tests, 13 advisor tests and 22 detached-job scenarios.
The runner suite has 19 cases with three explicit Python-only skips on each
architecture. Changed frontend Rust filters and final-package PTY checks passed.

On both native architectures, all seven footer captures have exactly five
nonempty lines below `›`, and replay through AP's classifier returns idle.
This covers ordinary idle and drafts, narrow panes, shortcuts and history search
with the Plus goal and full activity strip. See the
[x86 captures](https://github.com/WingsOfPanda/codex-plus/blob/0.163.0-plus.0.4.2/docs/evidence/footer-five-row/x86_64/report.json) and
[ARM captures](https://github.com/WingsOfPanda/codex-plus/blob/0.163.0-plus.0.4.2/docs/evidence/footer-five-row/aarch64/report.json).

Both native architectures passed seven 0.4.1/0.4.2 checks: fresh operator JSON,
actual execution and one callback, input/steering snapshots, quiet rollback over
0.4.2-written ledger and execution records, and maintenance holds entered by
either version and read/left by the other. Every settled row, schema and result
remained unchanged, with no workload replay. Both also passed six 0.4.0/0.4.2
helper-interoperability checks. All fixture cleanup completed with no survivors.
The [verification record](https://github.com/WingsOfPanda/codex-plus/blob/0.163.0-plus.0.4.2/docs/releases/0.163.0-plus.0.4.2/verification.json) and repeatable
gates in that directory record scope and identities.

## Fleet contract

The existing `tui.status_line` selection remains valid unchanged:
`["model-with-reasoning","context-remaining","weekly-limit","current-dir","pull-request-number","weekly-reset"]`.
`tui.status_line_use_colors = true` also remains unchanged. No new status
configuration key is introduced. The existing upstream
`tui.screen_reader_detection_done` may be written on first launch in a fresh home.

Use `quiet_checkpoint: true`, `executions: wait`, `daemon_restart: false`,
`session_restart: required`, `agents_md: null`, and
`retain: ["0.163.0-plus.0.4.1"]`. **0.4.1 is the qualified quiet rollback target
on x86 and ARM over 0.4.2-written records.** Once retention moves to 0.4.1,
0.4.0 becomes removable when unused. Keep every package referenced by a live
process or unresolved execution, including legacy 0.3.x sessions.

Restart loads the new frontend and adjacent helper. The tested 0.4.0/0.4.2 and
0.4.1/0.4.2 helper mixes passed without a new ledger/protocol correctness failure;
older TUIs still retain their existing admission timing/reporting defects until
restart. These checks do not claim two simultaneous native TUI interactions,
running-executor rollback or 0.3.x compatibility. Preserve disabled native goals,
global AGENTS instructions and the official daemon. Fleet-config owns pins,
staging and rollout.

## Limits

X86's raw bubblewrap UID-map probe is denied by host policy identically for
official Codex and Plus; both actual CLI read-only sandboxes passed. ARM passed
the resources gate. Full upstream tests and dedicated SSH logout/oracle-based
advisor foreground trials were not rerun for this release.

A successful but initially empty item-history page can still briefly project
Ultracode `unavailable` before a later status check establishes the exact turn.
That reproduced edge is fixed separately for planned 0.4.3 and is not included
here. The reported live blink was not captured, so its specific cause remains
unconfirmed.
