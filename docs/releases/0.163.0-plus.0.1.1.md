# Codex Plus 0.163.0-plus.0.1.1

Worker rows now preserve the reported model version and suffix instead of
shortening it to Sol or Astra:

```text
GPT-6.1-Sol (high) · glm upstream contribution · 2:53 · 175M tok
```

The redundant worker/workers word is removed. Custom/provider identifiers remain
intact; mixed-model groups stay mixed. Effort, shrinking active group counts,
elapsed time, reported tokens and dim styling retain their behavior. The entire
strip remains at most three rows including alerts and overflow, keeping AP's
idle prompt within the last six nonempty lines. Model labels are thread metadata,
not proof of per-turn provider routing. Narrow terminals retain existing clipping.

## Verification and limits

Focused source acceptance passed 36 Rust HUD tests plus fixture, packaging and
source guards. Each optimized extracted package passed 18 native terminal stages,
eight shell-policy cases and stock-daemon park/wake; 163 helper lifecycle/upgrade/
evidence tests; 11 interruption cases, seven recovery cases, normal completion,
nine cooperative scenarios, four upstream boundaries, rollback-read and two
upstream UI scenarios. These test counts overlap suite totals.

X86 passed 228 unittest methods and 35 isolated integration scenarios. ARM passed
163 helper tests, 35 source/packaging/runner tests on an unchanged rerun, 14 terminal
fixtures and the same required integration scenarios. Root acceptance independently
verified each exact archive: nine cooperative scenarios, four upstream boundaries,
rollback-read, two upstream UI cases, wrapper routing and before/after hashes.
Helpers were imported from the extracted packages; providers were loopback-only
with zero remote model requests. HUD refresh generated no additional model calls.

X86 passed eight of nine package gates. The raw bwrap namespace check retains
exit 1 because the host denies UID-map setup; official stock fails identically.
Supported CLI read-only sandbox enforcement passes for both. ARM passed all nine
package gates. Its first runner suite hit an existing `/proc` exists/read race
after a correctly terminated process disappeared. The unchanged complete 35-test
rerun passed; original failure logs and the first qualification wrapper's exit 1
are preserved. No payload or test edits were used to obtain that rerun.

Full upstream workspace tests, older glibc baselines and production rollout were
not run. Glibc 2.39 is the tested baseline, not a measured minimum. Stock callback
enqueue/ack ambiguity remains; no exactly-once model/tool execution is claimed.
The separate worker-shell-wait workflow is not part of this release.

## Rollout and rollback

All four boxes are still on stock 0.162.1 and Plus 0.162.1-plus.0.1.0. This release
can replace the staged 0.163.0-plus.0.1.0 candidate directly. The paired upstream
upgrade requires a quiet checkpoint, stock CLI/daemon 0.163.0, a scheduled daemon
restart, and session restart (`codex resume`). Fleet-config owns the rollout go.
Use `codex-stock` for daemon maintenance; the Plus `/daemon` menu stays read-only.
Cross-upstream helper transfers are intentionally refused even with protocol 1.

Plus ledger and callback states are unchanged. Upstream state migrations 0060
and 0061 add guardian feedback and unread-thread UI state; neither is a Plus
callback receipt migration. Private representative old-version history and
pending-queue readability passed, not a universal production rollback guarantee.
Every rollback uses a quiet checkpoint and restores the matching stock CLI/daemon
pair. Preserve previous and in-use package directories.

Installed packages, wrappers, shared daemon, host policy, active GLM work and live
registrations were left untouched by build and qualification. The park/shell
AGENTS.md block is unchanged. Evidence: `docs/evidence/plus011-release.json`.
