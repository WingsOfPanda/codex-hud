including CLI/resource discovery, native UI and terminal checks, helper
lifecycle, new advisor local/remote behavior, and existing explicit Astra checks.
Record failed/skipped checks and accepted host limits individually.
Development evidence in `docs/evidence/claude-advisor.json` is not a substitute.

Qualify quiet rollback to 0.4.3 over 0.4.4-written ledger/execution records,
both directions of maintenance holds, and mixed 0.4.3/0.4.4 helpers.
Exercise the advisor's persistent status/lock compatibility, remote-worker
version rejection, and in-flight ownership independently of the execution ledger.
Replay final native packaged footer captures against the installed compatible
AP classifier; do not claim a new AP release is necessary without evidence.

## Proposed rollout contract

Use `quiet_checkpoint: true`, `executions: wait`, `daemon_restart: false`,
and `session_restart: required`. Proposed `retain` is
`["0.163.0-plus.0.4.3"]` only after native rollback qualification passes.
That retires the 0.4.2 floor; it becomes removable once no process or unresolved
execution references it.

Drain advisor calls on both originating hosts and the central host before any
package switch. Install the central host first so new callers find the matching
worker. A helper version mismatch fails visibly; it is not a fallback or retry.
The final companion must describe any supported in-flight behavior separately;
the rollout relies on draining, not on assuming it is safe.

Restart sessions to load the Claude-aware TUI and the new global instructions.
Old 0.4.3 frontends reject Claude status/result identities for display; the
companion must distinguish this display limitation from actual result delivery.
